      AI-assisted development method

      AIDFlow helps developers and teams give AI coding agents a clear development process. The agent follows the flows; you approve key decisions.

      Add AIDFlow to a repository

      1. Download the Copilot reference
      2. Save it as .github/copilot-instructions.md in your repository. If that file exists, add the reference to it; keep your existing instructions.
      3. Ask your agent to use AIDFlow for your development task. It reads the online rules and retrieves the flows it needs.

      Your agent needs access to the linked files. You do not need to download the diagrams or set up this viewer.

      New GitHub repository with Copilot

      Start on GitHub without a local checkout. Copilot prepares the AIDFlow setup in a branch and opens a pull request. You do not need a product name or project description yet: the first task asks you questions in the pull request and waits for your answers before drafting the concept.

      Before you start: sign in to a GitHub account with access to Copilot's coding agent. Availability depends on your plan and organization policies; usage limits may apply. If the Jumpstart option is missing, create the repository normally and use the other setup method.

      Network access: GitHub's Copilot Jumpstart agent can read AIDFlow's public raw GitHub files. No repository Copilot firewall setting needs to be changed for AIDFlow.

      1. Open GitHub's new repository page. Choose the owner, repository name and visibility, and complete the repository settings. The repository needs a name, but it does not have to be the final product name.
      2. Find Jumpstart your project with Copilot (optional) and paste the prompt below as-is. No project description or product decisions are needed yet. Do not include passwords, tokens or other secrets.
      3. Create the repository with the prompt included. Follow GitHub's link to the Copilot task or pull request. Copilot works asynchronously; the session log shows its progress and any access problems.
      4. If AIDFlow retrieval fails, inspect the pull request body, comments or session log for the exact URL and fetch error. Report the blocker; do not change repository firewall settings as part of AIDFlow setup.
      5. Read the pull request and check that .github/copilot-instructions.md points to AIDFlow. After initializing the AIDFlow workspace, Copilot should post a comment titled Questions for the project owner. If the project purpose is not already clear, it should start by asking what the project should do or what problem it should solve, then ask only for additional information AIDFlow identifies as missing. Do not rely on questions appearing only in the pull request description. Copilot must not invent project details, draft or approve the concept, or implement product code before you respond.
      6. Whenever you want Copilot to process a reply, include @copilot in that pull request comment. You can bundle several answers into one comment, but a plain reply may not start or resume a task. Mention @copilot again when answering follow-up questions or asking Copilot to continue. If the initial questions are missing, use @copilot to ask for them. Do not merge the pull request yet.
      7. After your reply, Copilot should use your answers to draft .aidflow/concept.md and request your review. Ask for revisions in the pull request if needed. Approve only the exact concept version you agree with; merging alone is not approval.
      8. Once the setup and concept are satisfactory and required checks pass, merge the pull request when permitted. Continue with a new Copilot task or your local coding agent, asking it to read the repository instructions and resume AIDFlow from .aidflow/index.md.

      Jumpstart prompt

      Set up this new repository to use AIDFlow. Do not assume or invent a product name, project idea, users, requirements or technical choices.

Read https://raw.githubusercontent.com/vanlangenlabs/aidflow/main/setup.md and follow it. It links to aidflow.md and the flows; keep all sources on the same version. If you cannot access them, report the blocker instead of inventing the workflow.

      If the cloud session stops while waiting for approval, continue in a new task with the same repository records. Some web-reading tools cannot process the MIME type GitHub Pages assigns to .mmd files; use a permitted text-download tool to read the original source. If retrieval remains unavailable, provide an accessible, consistent copy of the instructions and flows before proceeding.

      GitHub documentation: Copilot coding agent

      AIDFlow provides the workflow, not the skills or tools. It guides your coding agent through development stages, checks and approvals. Your agent uses its own capabilities, available skills and tools to carry out the work.

      AIDFlow is in beta. Review the agent’s work and share feedback on unclear steps or unexpected behavior.
